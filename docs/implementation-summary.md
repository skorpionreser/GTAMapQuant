# Карта GTA Quant: сводка реализованных изменений

Этот документ описывает функциональность, добавленную в рамках развития карты,
администрирования, авторизации и качества кода.

## 1. Управление контентом

### Режимы карты

Добавлена сущность **Map Mode** — самостоятельный сценарий отображения карты.
Режим определяет:

- название и описание, видимые посетителю;
- порядок в списке;
- режим по умолчанию;
- системный статус;
- необходимость показывать стандартные метки по умолчанию;
- набор привязанных зон;
- набор привязанных меток.

Один маркер или одна зона могут состоять в нескольких режимах. Для этого
используются таблицы связей `MapModeMarkers` и `MapModeAreas`, а не один
внешний ключ в таблице маркера или зоны.

### Backend API

Добавлены endpoints:

| Endpoint | Назначение | Доступ |
| --- | --- | --- |
| `GET /api/MapModes` | Получить список режимов | Публичный |
| `GET /api/MapModes/{id}` | Получить зоны и метки режима | Публичный |
| `POST /api/MapModes` | Создать режим | `Admin` |
| `PUT /api/MapModes/{id}` | Изменить режим и его связи | `Admin` |
| `DELETE /api/MapModes/{id}` | Удалить режим | `Admin` |

Публичный endpoint контента принимает параметр `showStandardMarkers`. Он
позволяет включать или выключать стандартные метки, не меняя данные режима.

### Защита данных

- Системные режимы нельзя изменить или удалить.
- В приложении всегда должен оставаться хотя бы один режим по умолчанию.
- При назначении нового режима по умолчанию старый перестаёт быть таковым.
- При создании и изменении проверяются существование зон и меток, пустые GUID
  и дублирующиеся идентификаторы.

### Стандартные метки

В сущность и DTO маркера добавлено поле `IsStandard`.

- Администратор может менять его в форме маркера.
- Стандартные метки могут показываться во всех режимах по переключателю.
- Специальные метки показываются только в режимах, к которым они привязаны.

### Миграция

Добавлена EF Core миграция `AddMapModes`. Она создаёт таблицы режимов и связей,
а также начальные системные режимы «Карта мира» и «Игровые зоны».

## 2. Карта для посетителя

Страница `/map` теперь получает режимы динамически из API.

Пользователь может:

- выбрать режим из списка;
- увидеть название и описание выбранного режима;
- включить или выключить стандартные метки;
- увидеть только зоны, только метки или их комбинацию — в зависимости от
  выбранного режима.

Добавлены состояния интерфейса:

- загрузка данных;
- ошибка запроса;
- отсутствие доступных режимов;
- количество отображаемых объектов.

Стили панели карты и административной навигации дополнены правилами для
узких экранов.

## 3. Административная часть

### Навигация

В административной области есть переходы между разделами:

- `/admin/map-markers` — маркеры;
- `/admin/map-areas` — зоны;
- `/admin/map-modes` — режимы карты.

### Редактор режимов

Страница `/admin/map-modes` позволяет:

- создать режим;
- изменить название, описание и порядок;
- назначить его режимом по умолчанию;
- настроить показ стандартных меток по умолчанию;
- выбрать зоны и маркеры через чекбоксы;
- отредактировать существующий режим;
- удалить режим после подтверждения.

Системные режимы в таблице помечены и имеют отключённые кнопки редактирования
и удаления. Интерфейс показывает успешное сохранение и понятные сообщения об
ошибках.

## 4. Авторизация и безопасность

### Доступ к API

Все операции изменения маркеров, зон и режимов требуют JWT пользователя с
ролью `Admin`. Публичными остаются только read-endpoints, нужные посетителю
карты.

### Истёкшая сессия

Для всех административных запросов добавлена единая обработка HTTP `401`:

1. API-функция генерирует событие истёкшей сессии.
2. `AuthProvider` очищает `sessionStorage` и текущее состояние пользователя.
3. Интерфейс возвращается к состоянию неавторизованного пользователя.

Так пользователь не остаётся с устаревшим токеном и кнопками, которые уже не
могут работать.

### Production JWT

Секретный ключ не хранится в Git. Инструкция по передаче `Jwt__Key` через
секреты хостинга находится в [deployment.md](deployment.md).

## Необязательные следующие улучшения

Эти пункты сознательно не включены в текущую реализацию:

- CRUD категорий меток, их иконок и цветов;
- дополнительные роли помимо `Admin`;
- полноценный аудит действий администраторов;
- восстановление удалённых объектов из аудита.

## Что означает аудит действий

Аудит — это отдельный журнал бизнес-действий, а не обычные технические логи.
В будущем для каждой операции можно хранить:

- пользователя;
- действие: создание, изменение или удаление;
- тип и идентификатор объекта;
- дату и время;
- данные до и после изменения.

Это позволяет выяснить, кто изменил объект, и создаёт основу для безопасного
восстановления данных.
